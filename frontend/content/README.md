# City guides (`/interior-design/`)

Static, server-rendered city guides that sit alongside the React site. Every page is plain HTML at build time, so search engines see the full content without running JavaScript.

## Layout

| Path | What it is |
|---|---|
| `data/cities.csv` | Queue of the top 100 cities by population (Census 2011), Livspace service status, daily batches (`queue_batch`), page `status`. Single source of truth for status. |
| `data/facts/{city}.json` | Every claim used on a page: source URL, title, publisher, access date, exact quote, `city_specific`, plus claims removed and why. |
| `data/site.config.json` | Domain, relationship with Livspace, lead URL, author. **QA blocks publishing until the TODOs are filled.** |
| `data/link-graph.json` | Generated by production builds: inbound/outbound internal links for every page. |
| `content/interior-design/cities/{state}/{city}.md` | City guide content (Markdown + front matter). |
| `content/interior-design/guides/{topic}.md` | National topic guides (front matter `status`, `title`, `description`, `h1`). |
| `scripts/content/` | `build.mjs` (render), `qa.mjs` (gates), `queue.mjs` (queue), `build_cities.py` (how cities.csv was made). |
| `reports/` | QA output and daily reports. |

## Writing rules the tooling enforces

- Cite with markers: `{{f:fact-id}}` or `{{f:id-one,id-two}}`. Every sentence or table row containing a number needs one (BHK labels and list numbering are exempt). Markers render as numbered superscripts linked to the sources list.
- At least 8 city-specific facts, every H2 section of 120 words or more, 5–8 FAQs under an H2 called "Frequently asked questions" (each question an H3; FAQPage schema is generated from them).
- Max 30% five-word-shingle overlap with any other city page.
- Internal links only to built pages, at most one per target, descriptive anchors, at least one in-text link to another city.
- Title 50–60 characters, meta description 140–155.

The template adds breadcrumbs, disclosure, author line, the Livspace CTA (served cities only), the nearest-cities block (by distance, within 300 km or same state, excluding cities already linked in the text) and the "How we researched this page" section. State and national hubs are generated from whatever is built.

## Commands (run in `frontend/`)

```bash
npm run content:queue                       # status counts + next batch
npm run content:queue -- --set=pune:drafted # change status (published sets publish_date)
npm run content:qa                          # preview build + QA gates on drafted/qa_failed/ready pages
npm run content:qa -- --apply               # ...and set status to ready / qa_failed
npm run content:preview                     # noindex preview into .content-preview/
npm run build                               # Vite site + published city pages into dist/
```

Statuses: `queued → researching → drafted → (qa_failed ↔ drafted) → ready → published`. Only `published` pages reach `dist/`, the hubs and the sitemap (`sitemap-interior-design.xml`, also added to `robots.txt`).
